## Parser blind spots (findings for the audit)

1. **≤4 px serif subscript digits are doc-parse's hard floor on this frame.** Full frame destroys the whole 16-label X/Y family (58.7% regime); the crop cascade at 2–3× recovers 11 of 16 as clean subscript-inline strings — but X₄, X₅, X_{N-1}, Y₀, Y₁ are never read correctly at any scale tried (2×, 3× ×3). All five are judge-confirmed REAL with build-matching positions: the loss is the parser's, not the image's.
2. **Textless regions are structurally invisible.** The pooled 20-cell row (crop04) returns zero text and only a whole-span class token — no sub-coordinates, so parse-driven recursion terminates immediately; the region can never enter the text contract (wave-2 vision item 7 settles the 20 cells).
3. **Whole-span trailing class tokens on every parse** (`class_Picture` ×16, `class_Chart` ×1) carry no sub-coordinates → every parse-driven branch dies at birth; all real recursion in this tree was defect-triggered (garble triggers from L1 parses).
4. **Stacked-label merges are systematic** (2-line `Single vector…`/`Output Sequence`, 3-line `Word Embedding Vectors`/`Position Information Vectors`, 8-label Vector row → ONE line): words survive, multiplicity/geometry do not. The cascade's only structured read was crop12's `ranked_table` (chart-class) interpretation of the annotation column.
5. **Graphic-adjacent glyphs hallucinate stable prefixes:** the lollipop-marker `1`/`I` before C labels reproduced at full frame AND at 3× (call06) and died only in the tighter labels-row crop (call11) — a graphic misread can survive one recursion level.
6. **Reader variance on 13 px glyphs:** Σ read correctly twice at 3× in crop01 but as `Z` twice at 3× in crop07 — scale alone does not stabilize small-glyph OCR.
