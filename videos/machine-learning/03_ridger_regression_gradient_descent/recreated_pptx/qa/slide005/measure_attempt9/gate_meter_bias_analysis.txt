# Gate meter bias analysis — slide 005 lane slide005-judge9-1024192313, 2026-10-24

## What the deck's gate law measures
`pgrep -c -f analyze_image.py` is the fleet-wide occupancy meter
(`scripts/16_vision_gate.sh` + the deck's AGENTS.md judge rules). Its intent is
"how many analyzer calls are queued fleet-wide".

## What that meter actually counts
Every dispatched leg is a 3-process chain, and every link's argv contains the
literal string `analyze_image.py`:

  1. `bash scripts/16_vision_gate.sh timeout 1700 python3 .../analyze_image.py ...`
  2. `timeout 1700 python3 .../analyze_image.py ...`
  3. `/…/python3 …/analyze_image.py ...`          <- the ONE real analyzer

Additionally, any lane shell whose cmdline merely *mentions* the string counts
too (e.g. a monitor script's heredoc, an agent's `bash -c` dispatch wrapper).
And an INLINE probe (`pgrep -c -f analyze_image.py` typed into a `bash -c`)
counts the probing shell itself, inflating the reading by 1 more.

So gate_count ~= 3 x (legs in flight) + (shells mentioning the string).
The true analyzer concurrency is gate_count / 3, not gate_count.
